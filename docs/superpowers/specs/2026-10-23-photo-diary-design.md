# 사진 일기장 (Photo Diary) 설계

작성일: 2026-10-23

## 1. 무엇을, 왜

친구들과 카페에서 사진을 찍은 **그 자리에서 바로** 일기장에 남길 수 있는, 사진이 주인공인 아주 간단한 개인 일기장이다.

- 사용자 본인 혼자 쓰는 개인용이다. 공유나 SNS 기능은 없다.
- 아이폰 Safari에서 쓰는 웹앱이고, 홈 화면에 추가해 앱처럼 연다. 앱스토어에는 올리지 않는다.
- 성공 기준: 앱을 열고 몇 번만 눌러서 사진과 짧은 멘트를 남길 수 있고, 나중에 달력에서 날마다 대표사진을 보며 그날을 블로그 글처럼 다시 읽을 수 있다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- 빠르게 기록하기: 카메라나 갤러리에서 사진을 고르고, 멘트(선택)를 달고, 저장한다.
- 달력에서 기록한 날은 대표사진으로 칸이 채워진다.
- 하루 화면은 사진과 멘트가 위에서 아래로 쭉 이어지는 블로그 형태다.
- 백업 파일로 내보내기와 불러오기를 할 수 있다.

**하지 않을 것** (사용자와 함께 정함)
- 서버, 로그인, 온라인 자동 백업
- 기분 이모지, 태그, 위치, 날씨 같은 추가 입력
- 잠금 비밀번호, 다크모드 (이번 범위에서 제외)
- 앱스토어 정식 앱

**실패로 보는 것**
- 기록까지 누르는 단계가 많거나 입력 칸이 많아서 "바로 남기기"가 느려지는 것
- 디자인이 요란하거나 튀는 것. 사용자는 "심플하면서 감도 있는" 느낌을 원한다.
- 사진이나 일기가 소리 없이 사라지는 것

## 3. 화면과 동작

### 3.1 메인 화면 (앱을 열면 처음 보이는 화면)
- 빈 종이 위에 **오늘 날짜**를 크게 쓴다(예: `22`). 그 밑에 `OCTOBER · THURSDAY`를 작게 쓴다.
- 그 아래에 한 줄을 쓴다: **"올해 N일을 남겼어요."** N은 올해 기록이 하나 이상 있는 날의 수다. N이 0이면 문구는 빌더가 정한다(예: "오늘 첫 페이지를 남겨보세요").
- 하단에는 작은 `TOUCH TO OPEN` 표시가 있다.
- **작은 `+` 버튼**: 튀지 않게 얇은 선으로 작고 조용하게 둔다. 누르면 오늘 날짜로 사진 추가를 바로 시작한다(3.4의 선택 시트).
- `+` 외의 아무 곳이나 누르면 **종이를 넘기는 효과**와 함께 달력 화면으로 넘어간다.

### 3.2 달력 화면
- 위쪽에 연도(작게)와 `N월`(크게)을 쓰고, 그 아래 요일 머리줄과 날짜 칸을 둔다. 칸은 세로로 조금 긴 비율(약 3:4)이다.
- 기록한 날은 그날의 **대표사진으로 칸이 꽉 찬다**. 날짜 숫자는 아주 작게, 사진 위에서도 보이도록 살짝 그림자를 준다.
- 기록 안 한 날은 비어 있고, 흐린 숫자만 보인다. 오늘은 밑줄 등 조용한 표시를 한다.
- **좌우로 스와이프하면** 지난달이나 다음달로 넘어간다.
- 날짜를 누르면 그날의 하루 화면이 열린다. 미래 날짜는 누를 수 없다(빌더 판단 사항, 아래 7절 참고).
- 달력에서도 오늘 기록을 바로 시작하는 작은 `+` 버튼을 둔다(추천 1번).
- 설정(백업/불러오기)으로 가는 작은 아이콘을 둔다.

### 3.3 하루 화면
- 위쪽 머리말에는 `WED · 2026`(작게)과 `10월 7일`(크게)을 쓴다.
- **기록이 없는 날**: 큰 `+` 칸 하나만 보인다.
- **기록이 있는 날**: 사진 → 그 사진의 멘트 → 다음 사진 → 멘트… 순서로 **아래로 스크롤하며 블로그처럼** 읽는다.
  - 사진마다 **찍은 시간**을 작게 표시한다(예: `14:32`).
  - 대표사진에는 작은 "대표" 표시를 한다.
  - 사진을 누르면 화면 가득 크게 본다.
- 사진이 5장보다 적으면 오른쪽 아래에 작은 원형 `+` 버튼이 있다. 새 사진은 맨 아래에 붙는다.
- **맨 아래에 "1년 전 오늘"을 둔다**: 작년 같은 날짜에 기록이 있으면 그날 대표사진을 작게 보여주고, 누르면 그날로 이동한다. 기록이 없으면 아무것도 보이지 않는다.

### 3.4 사진 추가 흐름
1. `+`를 누르면 아래에서 시트가 올라온다: **카메라로 찍기 / 갤러리에서 고르기 / 취소**
2. **카메라**: 바로 촬영 화면이 열린다. 찍으면 곧바로 멘트 쓰기 화면으로 간다.
3. **갤러리**: 남은 자리 수만큼 여러 장을 고를 수 있다(하루 최대 5장). 고른 사진이 남은 자리보다 많으면 앞에서부터 남은 자리만큼만 넣고, 몇 장이 빠졌는지 짧게 알려준다.
4. **멘트 쓰기 화면**: 사진과 멘트 입력칸을 함께 보여준다. 여러 장을 골랐다면 사진마다 입력칸을 세로로 이어서 보여준다.
   - 멘트는 **사진마다 하나**이고 **최대 10줄**이다. 비워도 된다.
   - 버튼은 `저장` 하나로 충분하다. 멘트가 비어 있으면 사진만 저장한다. (첫 시안의 "멘트 없이 저장" 버튼은 빌더가 판단해서 빼도 된다.)
5. 저장하면 하루 화면으로 돌아간다.

### 3.5 대표사진
- 따로 정하지 않으면 그날 **첫 번째 사진**이 대표사진이다.
- 사진을 **꾹 누르면** 메뉴가 나온다: **대표사진으로 지정 / 위로 이동 / 아래로 이동 / 삭제**
- 대표사진으로 지정한 사진을 삭제하면 다시 첫 번째 사진이 대표사진이 된다.
- 대표사진을 바꿔도 피드 순서는 바뀌지 않는다.

### 3.6 수정
- 멘트를 누르면 그 자리에서 고칠 수 있다.
- 마지막 사진을 지우면 그날은 기록 없는 날이 된다(달력 칸이 비게 된다).
- 삭제하기 전에 확인을 한 번 묻는다.

### 3.7 백업 / 불러오기 (설정 화면)
- **백업하기**: 모든 사진과 일기를 파일 하나로 묶는다. 아이폰 공유 시트를 띄워서 '파일에 저장'으로 iCloud Drive에 둘 수 있게 한다.
- **불러오기**: 백업 파일을 고르면 일기를 복원한다. 지금 있는 데이터와 어떻게 합칠지는 7절을 따른다.
- 마지막 백업 날짜를 보여준다. 마지막 백업 뒤에 새 기록이 있고 백업한 지 2주가 넘었으면 설정 아이콘 옆에 작은 점 하나로 조용히 알려준다.

## 4. 디자인 방향: "필름 · 종이 감성" (사용자가 고름)
- 바탕은 따뜻한 미색(시안 `#f5f1ea`), 글자는 짙은 갈색빛 먹색(시안 `#3a332c`)이다.
- 글꼴은 명조 계열이다(시안에서는 Gowun Batang). 영문 작은 라벨은 자간을 넓게 준다.
- 장식은 최소로 하고, 얇은 선과 넉넉한 여백을 쓴다. 사진이 주인공이다.
- 화면 전환은 부드럽게 한다. 메인에서 달력으로 갈 때는 **종이 넘기는 효과**를 쓴다.
- 기준 시안: `docs/mockups/style-v2.html`(A안: 달력, 하루 화면)과 `docs/mockups/main-screen.html`(2번안: 메인 화면). 처음 화면 흐름은 `docs/mockups/flow.html`에 있다(디자인은 예전 것이고 흐름만 참고한다). 시안의 크기 비율, 여백, 선 굵기를 기준으로 삼고 다듬는 것은 빌더가 한다.

## 5. 기술 선택 (빌더 측 결정, 사용자는 플랫폼만 정함)
- **사용자가 정한 것**: 아이폰 Safari 웹앱(홈 화면에 추가), 앱스토어 없음, 백업은 파일 내보내기와 불러오기.
- **내가 정한 것** (사용자에게 아직 확인받지 않음):
  - Vite + TypeScript. 프레임워크 없이 가볍게 만든다(빌더가 작은 UI 라이브러리를 쓰는 것은 허용).
  - 저장소는 IndexedDB를 쓴다. 사진은 Blob으로 저장한다. `navigator.storage.persist()`를 요청한다.
  - 사진은 저장할 때 줄인다(긴 변 약 1600px, JPEG 품질 약 0.8).
  - 오프라인에서도 열리도록 PWA로 만든다(manifest, 서비스워커, 홈 화면 아이콘).
  - 백업 파일은 zip 하나에 JSON(일기 데이터)과 사진 파일을 담는다.
  - 배포는 GitHub Pages(무료, HTTPS)로 한다. 아이폰에서 카메라를 쓰고 홈 화면에 추가하려면 HTTPS 주소가 필요하다.
  - 새 폴더 `Desktop/photo-diary`에 별도 git 저장소로 만든다. 기존 `test` 저장소(테트리스)와는 분리한다.

## 6. 데이터 (대략)
- 날짜 기록: 날짜(`YYYY-MM-DD`), 사진 목록(순서 포함), 대표사진 id(없으면 첫 사진)
- 사진: id, 이미지 Blob, 멘트(최대 10줄), 찍은 시간
- 찍은 시간: 카메라로 찍으면 지금 시간을 쓴다. 갤러리 사진은 사진 정보(EXIF)에 촬영 시간이 있으면 그 시간을, 없으면 추가한 시간을 쓴다.
- 설정: 마지막 백업 시각

## 7. 빌더에게 맡긴 것 / 내가 정한 세부 사항
- **사진은 `+`를 누른 날짜에 들어간다(내 판단).** 갤러리 사진의 촬영일이 다른 날이어도 그 날짜로 옮기지 않는다. 시간 표시는 실제 촬영 시간(EXIF)을 쓴다. 사용자가 "날짜를 눌러서 그날에 올린다"고 설명했기 때문이다.
- **"오늘"은 자정에 바뀐다(내 판단).** 새벽에 전날 일을 남기려면 달력에서 전날을 눌러 추가한다.
- **지난 빈 날짜에도 기록할 수 있다(내 판단, 사용자가 반대하지 않음).** 시트는 어느 날이든 같다(카메라/갤러리).
- **백업은 연도별 파일로 만든다(내 판단).** 예: `photo-diary-2026.zip`. 1년 치를 한 파일에 담아도 수백 MB 수준이라, 아이폰에서 파일 하나로 다 묶으면 실패할 위험이 있다. 설정에서 연도를 골라 백업하고, 불러오기는 파일을 하나씩 받는다. 2주 알림은 "백업 뒤 새 기록이 생긴 연도"를 기준으로 한다.
- **데이터 보관의 위험은 사용자에게 설명했고, 사용자는 파일 백업을 골랐다.** 홈 화면 앱의 데이터는 일반 Safari 탭의 데이터와 따로 보관되므로 처음부터 홈 화면 앱으로 쓰도록 안내한다. Safari 탭으로 열었을 때는 "홈 화면에 추가" 안내를 한 번 보여준다.
- 배포에는 사용자의 GitHub 계정이 필요하다. 공개 저장소이지만 코드만 공개되고 일기 데이터는 폰에만 있다. 배포 단계에서 사용자와 함께 진행한다.
- 미래 날짜는 기록할 수 없다(내 판단).
- 10줄 제한: 줄바꿈 기준 10줄이고, 글자 수 상한(약 300자)을 함께 둔다(내 판단).
- 불러오기를 할 때 같은 날짜가 이미 있으면 사진을 합치되 5장을 넘지 않게 하고, 넘으면 백업 쪽을 우선한다… 이 규칙은 빌더가 단순하게 정한다. 가장 단순한 방법으로 "기존 데이터를 백업으로 교체(확인 후)"도 허용한다.
- 꾹 누르기 시간, 애니메이션 세부, 아이콘 모양은 빌더가 정한다.
- 테스트: 날짜 계산, 대표사진 규칙, 5장 제한, 백업 왕복은 자동 테스트로 확인한다. 화면은 아이폰 Safari에서 직접 확인한다.
